Legacy RequireJS micro frontends on federated React

Micro frontends that load through RequireJS can get their shared libraries from Module Federation, without being rebuilt.

The setup

Before Module Federation, many teams built micro frontends with webpack as AMD bundles loaded by RequireJS. Shared libraries like React and the UI kit are webpack externals. The page loads one copy of each, and every bundle asks for them with define(["react", "react-dom", "ui-kit"], ...).

The problem

Every component is tied to that one copy. Moving React to a new major means updating, rebuilding and releasing every team's component at once. Module Federation handles version sharing for new apps, but it cannot load these AMD bundles.

The bridge

A bridge FynApp serves React from federation under the AMD ids the bundles already ask for. A kernel add-on makes RequireJS fetch them through the bridge. Changing the legacy React major is now an edit to the bridge's mapping file. New FynApps on the page share that React or load their own major. Legacy components on one page still share one React.

Before Team A, B, C bundleswebpack AMD define("react") → Common bundleReact 18, one version for all
With the bridge Team A, B, C bundlessame files, not rebuilt define("react") → AMD add-on + bridge FynAppmapping file picks the major → Federated React18 or 19 ← New FynAppsshare it, or bring another major

Try it

  1. Switch where React comes from. "Legacy UMD files" is the old setup. The bridge modes serve React 18 or React 19 from federation to the same bundles, which were built against React 18.
  2. Load Team C. RequireJS fetches only widget-c.js and reuses the React already loaded.
  3. Check the React instances table. Each row is one copy of React, the apps that use it, and how many times its file was fetched.
